Assumptions to check against the real files:

I01, I02, I08: each rejects inputs the original already crashed on, so inputs it handled before produce the same output. I08 treats a lone comma as a decimal separator; a value like 1,250 with no decimal point would parse as 1.25.
I03: %Y/%m/%d is tried after the original format, so old inputs parse the same way.
I04: only the exact string N/A is treated as missing. Empty or other markers would still fail.
I05: I assumed amount_usd is already in dollars, so no currency conversion applies. If currency can be non-USD, the fix needs a conversion step.
I06: utf-8-sig strips a BOM when present and reads other files identically.
I07: the delimiter is chosen by comparing semicolon and comma counts in the header. Output stays comma-delimited, since the downstream format isn’t specified.
I09: 12% becomes 0.12; plain decimals take the original path.
